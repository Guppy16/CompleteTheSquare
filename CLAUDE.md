# Complete the Square

A 5x5 board game. The rules engine and the AI are a Rust crate in `wasm/`, compiled to
WebAssembly. The page in `square-game/` loads `square-game/ai.wasm` and runs the search
in a web worker. GitHub Pages serves the repo root: `index.html` is the game, and Jekyll
builds `docs/*.md` into pages (`assets/css/style.scss` is their dark theme).

- Rules: [docs/00-the-game.md](docs/00-the-game.md)
- How the engine works: [docs/](docs/README.md), one idea per page
- Open questions and the to-do list: [docs/18-next-steps.md](docs/18-next-steps.md)

## Layout

| file | holds |
|------|-------|
| `wasm/src/game.rs` | board state, moves, captures, win detection, symmetry tables |
| `wasm/src/search.rs` | evaluation, the search, the transposition table, the opening book |
| `wasm/src/parallel.rs` | multi-threaded search (native tools only) |
| `wasm/src/lib.rs` | the game session and every function the page calls |
| `wasm/tests/` | regression tests, including parallel-versus-serial agreement |
| `wasm/examples/` | the tools below |
| `square-game/script.js`, `worker.js`, `style.css` | the page; plain JS and CSS, no build step, no libraries |
| `square-game/online.js` | the Online tab: games against people through the Worker, by link or from the rated queue |
| `docs/img/` | SVG diagrams, generated by the tools below |
| `worker/` | the Cloudflare Worker: `/games` stores finished games in D1; `/mcp` is the connector for playing Claude (`mcp.js`; each game is a Durable Object, `game.js`; `rules.js` wraps `ai.wasm`; `board.html` is the board in the chat); `/online/*` runs games between people (`online.js`: a Room Durable Object per game, the Lobby for the rated queue; `ratings.js` is Glicko-2). Deploy: `set -a && . ./.env && python3 worker/deploy.py`; a test copy that the page on localhost uses: add `CTS_WORKER=cts-dev CTS_DATABASE=cts-dev-games` |

## Commands

```bash
python3 -m http.server 3000                    # serve the page: http://localhost:3000/
node --test worker/test/*.test.mjs             # Glicko-2 ratings (Node 22+)
CTS_URL=https://cts-dev.guppy16.workers.dev node worker/test/online.e2e.mjs   # online games, end to end
rustup target add wasm32-unknown-unknown       # once
cd wasm
cargo test --release                           # all tests
./build.sh                                     # rebuild square-game/ai.wasm; commit it with the Rust change
```

`ai.wasm` is committed, so the site deploys with no build step. Rebuild it after any
change in `wasm/src/`.

## Tools

All `cargo run --release --example ...` from `wasm/`:

| tool | what it does |
|------|--------------|
| `analyse -- "1. C3 A1  2. B2 D4" 10 16` | replay a game: what the engine would have played, every move scored, the expected line; depth 10, 16 threads |
| `arena -- 10 200` | the AI as Red against a human-like opponent (10% blunders, 200 games): the strength number |
| `validate_reply -- C3 A1 C5 40` | check opening-book candidates by play |
| `bench -- 11 1 4 16` | timing of the parallel search |
| `diagram -- --moves "1. A1 C3" --mark B2` | a board as SVG, for the docs |
| `tree_diagram -- --green A1,C1 --red B1` | a two-ply search tree with a board at every node |
| `animate_game -- "1. A1 B2 2. C3"` | an animated SVG of a game, like the README's |
| `animate_analysis -- 3` | an animated SVG of the Analysis tab over 3 moves, like the README's |

Depth 14 takes about half an hour, depth 16 about three hours on 16 threads. Run deep
searches one at a time.

## Conventions

- Docs pages name functions, not line numbers. Links to source files use full GitHub
  URLs (`https://github.com/Guppy16/CompleteTheSquare/blob/master/...`), because Pages
  would serve a relative link as a download.
- Fail loudly: unexpected states throw and show in the page's error banner, never a
  silent default.
- Scores are for the side to move, from -1 to +1; forced wins are just above ±1.
- The connector's tool names and arguments are public: Claude caches them per connector, so
  they only ever gain new tools and optional arguments, never renames or removals. A change
  to the tool list reaches a user only after they reconnect; a change to `board.html`, on
  their next page load.
